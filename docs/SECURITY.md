# EasyOA 安全说明与漏洞报告

本文说明当前安全机制、运行边界和私密报告方式。部署配置见[部署指南](deployment.md)，权限开发和负向测试见[开发指南](DEVELOPMENT.md)，普通功能问题见[Bug 提交指南](BUG_REPORTING.md)。

## Supported Versions

项目尚未公布固定的安全支持期限或各历史分支的补丁计划。报告请标明实际版本、Commit 与构建来源；维护者优先在当前代码确认问题，不承诺为每个旧版本回补。

| 版本 / 来源 | 当前范围 |
| --- | --- |
| `main` / `0.2.0` | 当前开发与待发布版本，接受问题报告；签名发行的远端发布仍待验收 |
| `v0.1.1` | 最近已发布的历史 MIT 版本；可报告问题，修复与回补安排以维护者确认和发布记录为准 |
| 更早版本 | 历史版本，不承诺持续维护；可提供影响范围和复现供排查 |
| 修改版 / 未验证构建 | 说明修改、Commit 与 About 状态；优先判断官方当前代码是否同样受影响 |

正式版本以 [GitHub Releases](https://github.com/YEXIAONAN/EasyOA/releases) 为准。开发构建、版本字符串或绿色 Badge 本身不证明部署来源或安全状态。

## How to Report a Vulnerability

**不要公开创建包含漏洞细节的 Issue、PR、评论、日志或截图。** 认证绕过、授权绕过、IDOR、RCE、SQL 注入、敏感数据泄露、会话劫持和文件越权访问均按安全问题私密处理；不确定时也先私密联系。

通过维护者 [YEXIAONAN GitHub 主页](https://github.com/YEXIAONAN)公开的邮箱 [yexiaonanair@outlook.com](mailto:yexiaonanair@outlook.com) 发送报告，建议主题为 `EasyOA security report: <简短问题>`。先发送脱敏摘要、影响版本和联系信息；敏感复现附件或大文件在确认接收方式后私密传递。

若仓库 [Security 页面](https://github.com/YEXIAONAN/EasyOA/security)以后提供 **Report a vulnerability**，也可使用 GitHub 的私密报告入口。入口未启用时仍使用上述邮箱，不改为公开 Issue，也不向无关账号发送细节。

## What Information to Include

- EasyOA 版本、Commit、Official / Development / Modified 来源分类与 About 原始状态。
- 操作系统、部署方式、相关代理 / 配置差异；修改版说明与官方代码的差异。
- 漏洞类别、受影响接口 / 资源、攻击前置条件与最低所需角色。
- 在自有隔离环境中的最小复现、预期权限与实际结果。
- 可能的影响范围、脱敏 RequestId / 日志 / 截图，以及建议修复或缓解方式（如有）。
- 可联系到你的方式及是否希望在公开披露中署名。

仅测试你有权操作的环境。复现使用合成数据，避免改变他人数据或尝试扩大生产影响。

## Do Not Publish Secrets

报告不需要真实账号密码、Session、Cookie、Token、API Key、TOTP Secret / 二维码、数据库密码或任何私钥。不要发送 `.env`、生产数据库 dump、完整备份或用户个人数据。用占位内容替代敏感字段；需要特殊材料时先私密商定最小范围。

若凭据已暴露，撤销相关会话并按实际密钥用途处理轮换和数据恢复。当前会话密钥还影响 TOTP 解密，见下方已知边界，不能将其视为无影响的配置替换。

## Disclosure Expectations

维护者确认收到后，会根据可复现性、影响和可用资源评估修复或缓解方式，并通过私密渠道沟通。项目不承诺固定响应时间、修复期限或所有旧版本回补。

在修复或缓解可用前，请勿公开利用细节、秘密或可识别用户数据。公开时间、影响范围和署名与维护者协商；修复状态以实际 PR、发布记录或安全公告为准。普通功能 Bug 不适用私密漏洞流程。

## 当前安全机制

### 认证、会话与初始化

- 默认使用 Session Authentication。会话 Cookie 为 HttpOnly、SameSite=Lax，生产为 Secure；开发 HTTP 关闭 Secure。认证凭据不放入 `localStorage`。
- 密码使用带算法标识的 BCrypt 哈希；登录失败阈值与临时锁定、密码策略由后端执行。写请求校验 CSRF，SPA 使用 Cookie / Header 流程与 XOR 请求处理。
- 登录建立会话时更换 Session ID。数据库会话元数据保存 Session ID 的 HMAC-SHA256 标识，活跃会话由过滤器复查。
- 登出、修改密码、账号禁用、系统角色变化及手动撤销按相应流程使会话失效；用户只能管理自己的设备记录。
- `/setup` 使用数据库初始化开关，一次创建组织与 ROOT；完成后常规初始化入口关闭。生产不创建演示账号。

### 后端授权与数据范围

前端隐藏按钮、路由守卫和条件渲染只负责交互。Controller / 应用服务独立校验认证、角色、组织与项目上下文、资源归属及查询范围。通过直接 API 调用也需要满足这些条件。

| 维度 | 边界 |
| --- | --- |
| 系统角色 | ROOT / ADMIN / MEMBER；系统管理权限与项目责任分开 |
| 项目角色 | OWNER / DEPUTY_OWNER / MEMBER；系统管理员可按管理范围查看，不自动获得项目管理权 |
| 任务责任 | 主负责人 / 副负责人 / 协作者；副负责人不能替换主负责人 |
| 资源与组织 | 档案联系方式、项目、任务、审批、附件、列表与搜索分别收敛到调用者允许范围 |
| 生命周期 | 归档项目只读；禁用账号与撤销会话不能继续沿用旧登录态 |

不可见项目和任务沿用 404 语义，减少资源存在性泄露。输入采用 DTO、校验与明确字段，API 不直接暴露 JPA 实体，错误不返回内部堆栈。权限仍需在每个新用例中复查，已有过滤器不能替代领域授权。

### TOTP 与高危操作

TOTP 使用 RFC 6238 的六位动态码、30 秒周期与相邻时间窗。绑定分生成 / 确认两步，未确认不启用；Secret 和 `otpauth://` URI 只在绑定阶段返回，之后状态接口不返回 Secret。自助解绑需要当前密码与动态码，ROOT 重置目标 MFA 经高危通道并撤销目标会话。

TOTP Secret 以 AES-256-GCM 加密存储。当前密钥用途与轮换限制见「已知边界」，不能仅凭“加密存储”推断部署密钥已实现分离。

ROOT 的审计清理、核心数据销毁、管理员 MFA 重置、安全策略调整和敏感导出统一使用 `SensitiveOperationService`：

```text
当前密码 → TOTP → 原因 → 影响预览 → 确认短语 → 执行 → 安全事件
```

关键密码 / 验证码失败也记录审计及安全事件。登录失败限制、密码最小长度、管理员 TOTP 要求由系统设置读取；启用管理员强制 TOTP 前应完成管理员绑定，避免失去登录能力。

### 审计与安全事件

`audit_logs` 保存业务操作证据，包含操作者、动作、资源、必要的 before / after、原因、IP、UA、RequestId、风险和时间。常规仓储与业务路径不提供编辑 / 删除；ROOT 按保留期清理须走高危操作，并写入 `security_events`。

`security_events` 从应用角度只追加，没有普通删除入口，包含 `previous_hash` / `entry_hash`。哈希链用于关联历史记录，不能单独抵御拥有数据库或宿主机控制权的攻击者。审计查询仅开放给 ADMIN / ROOT，普通用户的业务通知与这些日志分开。

日志、审计与安全事件不应记录密码、原始 Session、TOTP Secret 或部署密钥。保留期清理是受控例外，不能把业务审计描述为不可删除的永久记录。

### 附件与部署边界

- 附件由 `GET /api/files/{fileId}` 经认证、任务 / 审批可见性及文件授权下载，不作为公开 `/uploads` 静态资源。
- 磁盘使用随机存储名、分片与路径边界检查；元数据保留原名、存储名、MIME、大小、SHA-256、上传者、资源归属与时间。上传校验大小、空文件、危险扩展名与文件名，软删除保留记录；部分敏感下载写审计。
- 扩展名和 MIME 检查不等于恶意文件检测；当前未提供杀毒扫描或文件内容沙箱。
- 生产只有边缘 Nginx 暴露 Web 端口，API、Web 和 PostgreSQL 不映射公网端口。Nginx 终止 TLS、设置安全响应头并覆写转发 IP；仅开放必要健康信息，prod 关闭 OpenAPI。
- 宿主机、Docker 权限、TLS 私钥、部署配置、数据库及备份的访问控制仍由部署者负责。运行参数与操作步骤集中在部署指南。

### Official Release Verification

v0.2.0 的生产入口要求 Ed25519 签名和受保护文件 SHA-256 校验；签名或内容失败时拒绝启动。首次下载前从独立可信渠道取得公钥和指纹，单独的校验值不能证明发布者身份。信任流程见 [integrity/README.md](../integrity/README.md)。

公开只读 `/api/system/about` 提供版本、许可证、发布者与对应源码，后端根据编译公钥指纹、签名清单、VERSION 和实际运行 jar 判定 API 身份。About 的 Official 标签不代替 CLI 对整个部署的校验，也不能保护已经被控制的宿主机。

修改版保留真实构建状态并提供对应源码。发行完整性不是激活机制；项目没有 Pro、License Key、设备绑定或功能锁。AGPL 与历史 MIT 说明以 [LICENSE](../LICENSE) 和 [NOTICE](../NOTICE) 为准。

## 已知边界与待完成项

1. **密钥分离尚未实现。** 当前 `TotpCipher` 从 `EASYOA_SESSION_SECRET` 经 SHA-256 派生 TOTP 加密密钥，与开发宪法要求的用途分离存在差异。更换此密钥既影响会话匹配，也会使既有 TOTP 密文无法解密；不要在没有备份、迁移和账号恢复方案时直接轮换。当前没有可独立配置的 `EASYOA_ENCRYPTION_KEY` 或安全事件密钥。
2. **v0.2.0 尚未正式发布。** 已有本地发行实现和验收记录，真实 Tag 触发、GitHub Release 创建及资产上传仍待验证。详细证据见[发行验收记录](distribution-verification.md)；开发构建不能标为 Official。
3. **验证有范围。** 桌面 Web 是当前主要目标；发行镜像目前为 linux/amd64，Windows 部分运维命令尚不支持。签名验证、单个测试或构建成功不等于完整安全审计。
